# STT-008: Порівняльний тест якості + документація результатів

**Sprint:** STT Connectors
**Оцінка:** 3h

---

## Мета

Емпірично визначити оптимальну provider chain для українськомовних лекцій

## Що робимо

1. Скрипт порівняння `scripts/stt_compare.py`
2. Тест на реальному 10-15 хв українському аудіо (технічна лекція з суржиком)
3. Side-by-side порівняння, метрики
4. Документація результатів у `docs/stt-evaluation.md`
5. Фінальна конфігурація `STT_PROVIDER_CHAIN` в `.env.prod`

## Як робимо (коротко)

Створити `scripts/stt_compare.py`:
  - Вхід: шлях до аудіо, список провайдерів
  - Для кожного provider: транскрибувати, засікти час, зберегти результат
  - Output: таблиця порівняння + JSON report + per-provider .txt файли

Підготувати тестове аудіо:
  - 10-15 хв, українськомовна лекція, технічна термінологія
  - Бажано з суржиком (uk+ru mix) і кількома спікерами

Запустити тест і оцінити:
  - Загальна точність, суржик handling, технічні терміни, пунктуація
  - Таймкоди (spot check 5), speaker diarization
  - Cost і швидкість

Документувати і зафіксувати chain

## Очікуваний результат

Документований вибір оптимальної provider chain, `.env.prod` налаштований

## Тестування

**Автоматизовано:**
- `stt_compare.py` з `--dry-run` (mock providers) працює
- Output JSON має правильну структуру

**Human control — ГОЛОВНИЙ ТЕСТ СПРІНТУ:**
1. Прочитати транскрипти від трьох провайдерів
2. Оцінити кожен (1-10): точність, суржик, терміни, пунктуація, таймкоди, diarization
3. Визначити winner і runner-up
4. Зафіксувати `STT_PROVIDER_CHAIN` в `.env.prod`
5. Задокументувати в `docs/stt-evaluation.md`

## Сумісність з існуючим кодом

- Скрипт використовує production STTProvider classes — validation by design
- `.env.prod` оновлений, deploy підхопить нові змінні
